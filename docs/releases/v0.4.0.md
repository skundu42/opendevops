# opendevops v0.4.0

v0.4.0 adds repository and release inspection and machine-readable preflight checks, and fixes
failure reporting and request limits in unattended operations.

## Highlights

- Inspect repository metadata and releases with `gh repo view|list` and `gh release view|list`.
  These commands use the read-only token and existing flags; mutations, cloning, downloads,
  browser launching, and `--hostname` overrides remain denied.
- Use `opendevops config check --json` in CI. It returns `ok`, `successes`, `warnings`, and
  `failures`, with exit status 1 for failed checks or invalid configuration. Combine it with
  `--live` for authenticated health probes. Invalid remote TLS files become report failures.
- Scheduled runs that return errors or budget stops no longer update success timestamps.
  Thread creation is included in the job deadline, and timeout reporting survives gateway
  cancellation handling and cleanup failures.
- Webhook runs project returned errors and budget stops into operational telemetry without
  exposing provider error details. Oversized streamed requests stop at the body limit even
  when `Content-Length` is absent or incorrect.
- Common execution wrappers now produce the explicit `interpreters-hard-deny` audit rule
  instead of a generic default denial.

## Upgrade notes

- No configuration migration or dependency upgrade is required from v0.3.0.
- Existing workspaces retain their policy files. To enable the new GitHub reads or explicit
  wrapper denials, review and copy the updated `config/policy/packs/gh-read.yaml` and
  `config/policy/base.yaml` into your policy directory. Preserve local policy customizations.
- Scheduler success timestamps may stop advancing for jobs that were previously counted as
  successful despite errors or budget stops. Check the recorded job outcomes when investigating.
- JSON warnings alone do not fail preflight. Human-readable output remains the default.

## Install

```sh
uv tool install "opendevops[checkpoint,ssh]==0.4.0"
```

For a Compose deployment, download the source-free bundle:

```sh
curl -LO \
  https://github.com/skundu42/opendevops/releases/download/v0.4.0/opendevops-deploy-0.4.0.tar.gz
tar -xzf opendevops-deploy-0.4.0.tar.gz
cd opendevops-0.4.0
cp .env.example .env
docker compose up -d
```

The bundle pins `ghcr.io/skundu42/opendevops:0.4.0` and supports `linux/amd64` and `linux/arm64`.
Existing deployments should retain their secrets, configuration, and persistent volumes.
