# Configuration reference

Configuration lives in three YAML files under `config/`, plus a `.env` for secrets and the
`config/policy/` directory ([policy guide](policy.md)). Loaders are pydantic-settings models in
`src/opendevops/config.py` — invalid or incomplete config **fails the boot**, it never degrades.

Set `OPENDEVOPS_CONFIG=/path/to/config.yaml` to point the process at a non-default location;
`models.yaml`, `budgets.yaml`, and the policy dir are resolved as its siblings.

## The name-not-value convention

Every secret in every config file is the **name of an environment variable**, never a value —
`token_env: OPENDEVOPS_GH_TOKEN`, not the token itself. Values live in the process environment
(locally via `.env`). Consequences:

- config files are committable and diffable;
- a route/pack whose named env var is unset fails **closed** (503 for webhooks, boot refusal for
  packs) — never "auth disabled";
- the executor injects credential *values* into subprocesses by looking up the configured names,
  so the model never sees them.

## `config/config.yaml`

### `targets` — what the agent may touch, and with which credentials

```yaml
targets:
  kubernetes:
    kubeconfig_ro: ~/.kube/agent-view.yaml   # generated by ops/k8s/gen-kubeconfig.sh
    kubeconfig_rw: null                      # legacy staging-only fallback
    kubeconfig_rw_by_environment:            # production never falls back to kubeconfig_rw
      staging: ~/.kube/staging-agent-rw.yaml
      prod: ~/.kube/prod-agent-rw.yaml
    allowed_contexts: []                     # REQUIRED before first run — fail-closed gate
  github:
    token_env: null              # name of the env var holding a read-only fine-grained PAT
    token_env_rw: null           # name of the env var holding a distinct WRITE PAT (gh-write pack)
    write_repos: []              # owner/repo allowlist for gh api writes; empty ⇒ all writes deny
  aws:
    credential_env: []           # e.g. [AWS_ACCESS_KEY_ID, AWS_SECRET_ACCESS_KEY, AWS_REGION]
  gcloud:
    credential_env: []           # e.g. [GOOGLE_APPLICATION_CREDENTIALS, CLOUDSDK_CORE_PROJECT]
  azure:
    credential_env: []           # e.g. [AZURE_CLIENT_ID, AZURE_TENANT_ID, AZURE_CLIENT_SECRET]
  ssh:
    hosts: []                    # host allowlist; empty ⇒ no host reachable
    user: null                   # pinned remote login user
    key_env: null                # name of the env var holding the PATH to the private key
    key_passphrase_env: null     # optional passphrase env var name
    known_hosts_path: null       # pinned known_hosts; null ⇒ ssh_run refuses (never disables checking)
    port: 22
```

**Coverage gates**: an unconfigured family (empty `credential_env`, null `token_env`, empty ssh
config) makes its policy pack refuse to boot — an allow can never outrun its credentials. Cloud
credentials must point at read-only roles whose IAM explicitly **Denies** secret-material reads;
the policy packs are the compensating control on top of that role, not a substitute.

### `execution`

```yaml
execution:
  cmd_timeout_seconds: 60
  output_max_chars: 50000
  env_allowlist: [PATH, HOME]
  trusted_path: /usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
```

Default subprocess timeout, output truncation threshold (full scrubbed output spills to the
virtual FS), and the safe base environment. `env_allowlist` must contain exactly `PATH` and `HOME`;
both are constructed values, not forwarded from the parent. `trusted_path` accepts only absolute
directory entries.

### `executor` — local vs remote execution

```yaml
executor:
  mode: local                # local (default, reviewed) | remote (EXPERIMENTAL — see gates)
  url: null                  # remote: executor service base URL
  signing_key_env: null      # remote, agent side: env var name of the ed25519 PRIVATE key (base64, 32 raw bytes)
  verify_key_env: null       # remote, service side: env var name of the ed25519 PUBLIC key
  secret_source: env         # {{secret:NAME}} backend (env-backed; vault can plug into the same seam)
  secret_env_prefix: ""      # optional namespace prefix for {{secret:NAME}} lookups
```

A standalone `{{secret:NAME}}` argv entry declares a child environment variable and is removed
before execution. Use it only with programs that natively read that variable (for example
`PGPASSWORD`). Embedded references are rejected; there is no shell expansion.

`mode: remote` is not production-deployable until the gates in `ops/executor/README.md` close —
see [security model](security-model.md#the-executor-split-moderemote).

### `audit`, `policy`, `state`

```yaml
audit: {dir: ./audit}        # per-run hash-chain files <run_id>.jsonl
policy: {dir: ./config/policy}
state: {dir: ./state}        # CLI checkpointer sqlite (created 0o700)
```

### `server` — service mode (LangGraph Server)

```yaml
server:
  url: http://localhost:8123           # external URL (through Caddy); unset ⇒ service mode disabled
  api_key_env: LANGGRAPH_API_KEY       # env var name for the server API key (null ⇒ no auth)
  alertmanager_token_env: null         # bearer token env var name for /webhooks/alertmanager (+ run-complete); null ⇒ 503
  github_webhook_secret_env: null      # HMAC secret env var name for /webhooks/github; null ⇒ 503
  source_allowlist: []                 # client IPs allowed on the Alertmanager route (empty ⇒ all)
  webhook_environment: staging         # policy environment for webhook-initiated runs
  dashboard_auth_mode: oidc            # oidc (deployment) | static (local development)
  dashboard_token_env: null            # static mode only
  dashboard_session_backend: redis     # redis for replicas/restart-safe revocation; memory for dev
  dashboard_session_redis_url: redis://redis:6379/2
  dashboard_session_ttl_s: 3600        # opaque server-side session lifetime (maximum eight hours)
  dashboard_cookie_secure: false       # set true whenever the public endpoint uses HTTPS
  oidc:
    issuer: https://id.example.com/realms/operations
    client_id_env: OIDC_CLIENT_ID
    client_secret_env: OIDC_CLIENT_SECRET
    redirect_uri: https://ops.example.com/dashboard/oidc/callback
    scopes: [openid, profile, email]
    roles_claim: groups                 # dot-separated claim path is supported
    role_mappings:
      viewer: [devops-readers]
      operator: [devops-operators]
      approver: [change-approvers]
      admin: [devops-admins]
    default_roles: []                   # no matching role fails login by default
```

Inside the server container, `OPENDEVOPS_SELF_URL` (default `http://localhost:8000`) overrides
`server.url` for the webhook app's *own* gateway only — see
[deployment](deployment.md#two-urls-one-server).

OIDC discovery validates the configured issuer exactly. The authorization-code flow uses state,
nonce and PKCE; ID tokens are signature-, issuer-, audience-, expiry-, issued-at- and
nonce-validated. A successful login returns an opaque `HttpOnly`, `SameSite=Strict` cookie scoped
to `/dashboard`; the cookie contains no token or claims. Session revocation deletes server state
immediately. Every state-changing API also requires a session-bound CSRF header. Set
`dashboard_cookie_secure: true` behind HTTPS.

### `control_plane` — capability grants and loop controls

```yaml
control_plane:
  database: ./state/control-plane.sqlite3
  production_requires_independent_approval: true
  enforce_runtime_grants: true
  grant_required_environments: [prod]
  max_rw_actions_per_run: 12
  max_identical_rw_actions_per_run: 2
  max_consecutive_failures: 3
  default_grant_ttl_s: 3600
  max_grant_ttl_s: 86400
  minimum_cooldown_s: 5
```

The SQLite ledger is shared by the dashboard, CLI and policy middleware. In a multi-replica
deployment, place it on a single-writer durable volume until the control ledger gains a Postgres
backend. `grant_required_environments` identifies the environments where every rw execution needs
an active grant. Production Kubernetes apply/rollout/scale/delete reaches this gate; real apply is
still blocked until the same manifest passed a server-side dry-run in the current run.

A grant is deliberately narrower than arbitrary configuration: capability, reviewed target set,
reason, expiry, operation ceilings, repeat ceiling, failure threshold, cooldown, and dry-run
requirement. Runtime resource enforcement remains in the policy pack's parsed target allowlists;
the target set is the human-reviewed scope recorded with the grant. A grant can tighten an
existing policy allow/escalation but can never override a deny, target allowlist, credential
boundary, or dry-run requirement.

### `slack`, `scheduler`, `principals`

```yaml
slack:
  bot_token_env: null                  # xoxb- token env var name; null ⇒ adapter refuses to start
  app_token_env: null                  # xapp- token env var name
  default_channel_environment: staging
scheduler:
  jobs_file: scheduler/jobs.yaml
  principal: scheduler                 # audit user + daily-budget scope for scheduled runs
principals: {}                         # external id -> {principal, profile, roles:[operator,...]}
```

## `config/models.yaml`

```yaml
agents: {main: opus, summarizer: haiku, log_summarizer: haiku}
aliases:
  opus: anthropic:claude-opus-4-8
  sonnet: anthropic:claude-sonnet-5
  haiku: anthropic:claude-haiku-4-5
pricing:                                   # USD per MTok
  anthropic:claude-opus-4-8:  {input: 5.00, output: 25.00, cache_read: 0.50, cache_write: 6.25}
  anthropic:claude-sonnet-5:  {input: 3.00, output: 15.00, cache_read: 0.30, cache_write: 3.75}
  anthropic:claude-haiku-4-5: {input: 1.00, output: 5.00,  cache_read: 0.10, cache_write: 1.25}
fallback_pricing: error                    # unpriced model ⇒ refuse to boot
```

- `agents` assigns a model alias per role: `main` (the agent), `summarizer` (context compaction),
  `log_summarizer` (the one permitted subagent).
- Multi-provider is free: aliases accept any `provider:model` string the underlying
  `create_deep_agent` accepts — the price table is the only thing to extend.
- **An unpriced model is an unmetered model**, so `fallback_pricing: error` refuses to boot if any
  referenced model has no price row.

## `config/budgets.yaml`

```yaml
trip_ratio: 0.9                        # jump-to-end at 90% of the per-run cap
fail_mode_on_counter_outage: closed    # daily-counter outage ⇒ refuse new runs
per_run:
  default:     {usd: 2.00, model_calls: 50, tool_calls: 100, shell_calls: 30,
                recursion_limit: 250, wall_clock_s: 900}
  profiles:                            # profiles override the default per key
    interactive: {usd: 5.00, wall_clock_s: 1800}
    scheduled:   {usd: 2.00, model_calls: 40}
    incident:    {usd: 10.00, wall_clock_s: 3600}
daily:
  global_usd: 50.00
  per_principal_usd: 25.00
  backend: sqlite                      # sqlite (default, single-process) | redis (service mode)
  # redis_url: redis://redis:6379/0    # REQUIRED when backend: redis
```

See [budgets](budgets.md) for what enforces each number.

## Validation

```sh
uv run opendevops config check
```

loads and validates everything, printing counts (allowed contexts, budget profiles, priced
models) or the exact validation error. Run it after every config change; the same validation runs
at every boot.
